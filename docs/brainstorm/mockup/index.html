Ka0s DPS Race — windows & flows

How the timed dummy race looks and moves: the Race HUD in each of its states, the Results window (history, run detail and personal bests), the settings that carry the scoring rules, and the chat output. The design spec is docs/superpowers/specs/2026-10-23-dps-race-pve-design.md; section numbers below (§) point into it.

01 · The flowOne race, start to result

Click a step to jump the HUD below to that state. Every transition comes from an event or the clock, never from a damage number, because damage numbers can't be read during combat (§4, §8 rule 2).

Incomplete — combat drops before the buzzer (you stopped, died, the dummy reset). The run is stored and marked, and never counts toward bests.
Reloaded — the run was saved when it started. After /reload it carries on waiting and reads the result by session ID. It's flagged if the buzzer passed during the reload.
Lost — the session is gone (logout, meter reset). The metadata is kept, there's no score, and the HUD says why.
Cancel — at any point before the result. Nothing is stored.

Movable and resizable (default 300×360). The header and footer stay the same and the body changes with the state. The Running state animates here so you can see the countdown and the bars filling.

06 · Rules the UI followsWhy it looks the way it does

No live percentages, no live sortingDuring combat every number is secret: it can be shown but not divided or compared. Live rows show bars and amounts in Blizzard's order. The result shows %.
Your DPS, not the meter'sDPS = damage ÷ race length, from the addon's own clock. The meter's figure is diluted by the time it takes combat to drop, so it's shown muted and only for reference.
Flags inform, never voidLate casts, damage restarting and reloads add a flag chip. Only an incomplete run (combat ended before the buzzer) stays off the bests.
Arming needs you out of combatThe clock starts on a new meter session, and one is only created when combat starts. The Arm button says so when it's disabled.
Waiting is safeThe run is saved the moment it starts and read by its session ID later, so a dummy stuck in combat, or a reload, only delays the result.
Target count is metadataThe meter merges identical dummies into one row, so the count comes from the catalog or the stepper. It's never scored.
